# 社区采样与贡献指南 v1.0

> 面向贡献者：如何用 3 条命令完成一次合格采样，并把它提交到规则库。
> 核心理念（来自 v1.1 决策）：**贡献观测，不贡献路径**。观测是脱敏真机事实，规则由观测聚类派生。
> 本指南对应工具链：`config/observe-config.json`（配置）+ `PhoneFiles.Probe.Console`（采样）+ `tools/validate_observation.py`（校验）。

---

## 0. 你要做什么（30 秒版）

1. 手机用数据线连电脑，USB 模式选 **「文件传输 / MTP」**，解锁屏幕。
2. 跑一条命令采样（只读，绝不改动手机）：
   ```
   dotnet src/PhoneFiles.Probe.Console/bin/Debug/net8.0-windows7.0/PhoneFiles.Probe.Console.dll \
     observe --from-adb --out contributions/observations/<你的机型-日期>/
   ```
3. 跑校验：`python tools/validate_observation.py --all contributions/observations/`
4. 看到全 `[OK]`，把生成的目录作为 PR 提交。

就这样。不需要装 Visual Studio、不需要改 C# 代码、不需要重新编译。

---

## 1. 前置准备（一次性）

| 需求 | 是否必须 | 说明 |
| --- | --- | --- |
| .NET 8 Runtime 或 SDK | 必须 | 运行探针；`dotnet --version` 应 ≥ 8.0 |
| Android 手机 + 数据线 | 必须 | USB 模式选「文件传输/MTP」，**解锁屏幕**（锁定state 下 WPD 节点会是 Disconnected） |
| ADB（可选） | 推荐 | 有了它 `--from-adb` 能自动填型号/系统版本，避免手填出错；装了 Android SDK 或单独 platform-tools 即可 |
| Python 3 | 校验用 | 仅运行校验脚本，零第三方依赖 |

> 隐私承诺：整个流程**只读手机、不上传任何文件内容/文件名/账号 hash**。发出的 observation 只含目录名、粗分桶、扩展名分布。详见 §5。

---

## 2. 采样（核心 3 步）

### 步骤 1：确认设备已就绪

```bash
dotnet <probe.dll> list
```

- 看到设备名（如 `Redmi Note 7 Pro` / `maker: Xiaomi`）→ 就绪，继续。
- 报 `No MTP devices found` → 按下方「连不上怎么办」排查。

### 步骤 2：（可选）看看目录结构

```bash
dotnet <probe.dll> tree --max-depth 2
```

这一步帮你了解这台手机的卷结构。**注意有多个存储卷时**（如内置存储 + TF 卡），探针会自动**每卷各出一份** observation，不会混淆同名目录（Download/Recordings 可能两卷都有）。

### 步骤 3：采样

标准命令（推荐，自动填元数据）：

```bash
dotnet <probe.dll> observe --from-adb \
  --region CN \
  --out contributions/observations/<oem>-<model>-<YYYYMMDD>/
```

输出示例：
```
Loaded config v1 with 10 targets.
--from-adb: adb=... model=RMX5010 os=17 sdk=37
Wrote contributions/observations/gt7pro-2026-11-21/obs_内部共享存储空间.json
```

若无 ADB，可手动指定（**务必核实版本，别照抄上一台**）：

```bash
dotnet <probe.dll> observe \
  --oem xiaomi --model "Redmi Note 7 Pro" --os 16 --sdk 36 --region CN \
  --out contributions/observations/redminote7pro-2026-11-21/
```

命令参数一览（也可见 `dotnet <probe.dll> --help`）：

| 参数 | 作用 |
| --- | --- |
| `--device X` | 指定设备 PnP id 或名称片段（多台设备时） |
| `--oem/--model/--os/--sdk/--region` | 手动填设备元数据 |
| `--from-adb` | 从 `adb getprop` 只读填充上述字段（缺的才填，手填优先） |
| `--adb PATH` | 指定 adb.exe 路径（自动探测失败时用） |
| `--out DIR` | 输出目录（**每卷一份** `obs_<卷名>.json`） |
| `--config FILE` | 指定观察配置（默认自动发现 `config/observe-config.json`） |

## 3. 校验（提交前必做）

```bash
python tools/validate_observation.py --all contributions/observations/
```

全绿才提交：
```
[OK]   .../obs_内部共享存储空间.json  entries=10
合计 4 份，通过 4，失败 0
```

校验器做三件事：
1. **Schema 结构**：字段齐全、类型正确、枚举合法（对照 `rules/schema/observation.schema.json`）。
2. **隐私红线**：`filenameSamples=false`、`deviceIdHash` 格式、扫描伪扩展名（`.removed-20240201-...`）和疑似 IMEI/序列号。
3. **配置一致性**：entries 里的节点是否都在 `config/observe-config.json` 的 targets 内（防止改了配置忘了提交）。

任何 `[FAIL]` 都要修到 `[OK]` 才能提交。校验器零依赖、完全离线。

---

## 4. 提交

1. PR 内容：只加 `contributions/observations/<目录>/` 下的 `obs_*.json`。
2. PR 描述里写清：机型、ROM、Android 版本、通道（mtp/adb）、有无 TF 卡。
3. 2 名 trusted contributor review 通过后进入规则派生流水线（见 `rules/GOVERNANCE.md`）。
4. 你贡献的是**观测事实**，不是规则；规则由维护者从多次观测聚类派生，带置信度与版本。

---

## 5. 隐私红线（不可逾越）

探针只发这些：
- 目录名（`nodePattern`，WPD 相对节点名，如 `DCIM/Camera`）
- `exists: true/false`（**不可见同样有价值**）
- 子节点数量分桶、体积分桶、扩展名分布（最多 4 种，如 `jpg:0.82,mp4:0.15`）
- 去标识的设备指纹（`sha256:` 加盐 hash，仅用于去重）

探针**绝不**发：文件名、文件内容、账号 hash 原文、IMEI/序列号、精确时间戳、精确字节数。

> 校验器会把违规样本判为 `[FAIL]`。人工提交（手写 observation）同样受这些红线约束。

---

## 6. 观察目标可维护（社区能改的清单）

想观察新的目录（比如某厂商的 `ColorOS`、`Audiobooks`）？不用改代码：

编辑 `config/observe-config.json` 的 `targets` 数组，加一行：
```json
{ "nodePattern": "Audiobooks", "canonicalLabel": "unknown" }
```

- `nodePattern`：WPD 相对节点名，用 `/` 分段；`*` 匹配单层任意目录（如 `Android/data/*/files`）。
- `canonicalLabel`：只能取 `camera_media / screenshots / downloads / recordings / unknown`。
- 分桶边界在 `buckets` 里改；root 映射在 `rootMapping` 里改。

改完 config 后采样即刻生效（探针每次运行都重新读配置）。**若你改了 targets，请把 config 改动也放进 PR**，校验器的「配置一致性」检查依赖它。

---

## 7. 连不上怎么办

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `list` 报无设备，但设备管理器里有 | WPD 节点状态 `Disconnected` | 手机解锁屏幕，重新插拔数据线，再试 |
| 设备名对不上（想采样 A 却列出 B） | 同时插了多台 | 用 `--device <名称片段>` 指定 |
| 手机上没反应 | USB 模式不是「文件传输」 | 下拉通知栏，把 USB 用途改成「文件传输/MTP」 |
| WPD 节点一直 Disconnected | 驱动/USB 口问题 | 换 USB 口、换线；Windows 更新里重装 MTP 驱动 |

## 8. 常见问题

**Q：为什么我的手机 MicroMsg 目录可见但 size=0？**
目录存在 ≠ 聊天数据可读。MicroMsg 常常是空壳或只有临时文件；`EnMicroMsg.db` 解密明确不在本项目范围。如实记录 `exists:true` + `sizeBucket:0` 即可，这正是规则库需要的证据。

**Q：一台手机有两个卷，会生成几份 observation？**
两份（每卷一份），`root` 分别为 `internal_shared`（内置）和 `sdcard1`（TF 卡）。这是刻意设计——同名目录在两卷上内容不同，不能合并。

**Q：Android 版本填哪个？getprop 和 fingerprint 冲突怎么办？**
`--from-adb` 会以 `getprop release/sdk` 为准，并在冲突时打印 `[WARN]`。你在 PR 描述里注明冲突即可，维护者会保留多源信息，不做外推。

**Q：可以不联网采样吗？**
可以。整个采样和校验流程完全离线，不上传任何东西。提交 PR 时才联网（且只传 observation JSON）。

# 规则库治理规则（最小可行）

本文件是 v1.1 文档 §1.2.5 的落地版，定义规则库从观测到上线的完整生命周期。规则库是独立数据资产，许可见 [LICENSE-DATA](../LICENSE-DATA)。

## 0. 基本立场

- **观测是事实，规则是派生品**。维护规则的正确方式是提交观测，不是手改 `rules/rules/*.yml`。
- **探测优先于查表**。运行时以现场枚举与指纹为主，规则只给语义与排序，绝不作为唯一判定。
- **错误代价不对称**。一条错误标签 → 用户误删 → 不可恢复 + 信任崩塌 + 潜在法律责任。宁缺毋滥。

## 1. 贡献门槛

| 项 | 规则 |
| --- | --- |
| 真机 | 必须是真实设备上实际观测，不接受凭记忆或猜写 |
| 设备指纹 | 必须带 OEM / model / osVersion / sdk / region；romBuild / romFamily 尽量全 |
| 通道 | 必须明确 `channel`（mtp / adb），不得混填 |
| 脱敏 | 必须通过去标识扫描；`filenameSamples` 必须为 false |
| 匿名防灌水 | 匿名贡献需邮箱验证； trusted contributor 免验证 |

## 2. 自动校验（不通过直接拒绝）

1. **节点存在性**：`nodePattern` 格式合法，不含盘符、不含账号 hash 原文、不含文件名。
2. **指纹格式**：`fingerprint` 符合 `dir:...|ext:{...}` 结构，扩展名比例为 0–1 且总和≈1。
3. **去标识扫描**：扫描 `deviceIdHash` 格式、禁止项关键词、疑似 IMEI/序列号模式。
4. **同条件冲突检测**：相同 OEM+ROM 族+SDK 区间+通道+节点下若已有稳定规则且结论冲突，标记待复核而非直接入库。
5. **Schema 校验**：对照 `rules/schema/observation.schema.json`，字段齐全且类型正确。

## 3. 审核流水线

```
提交 → 自动校验 → 待复核(pending_review) → 2 名 trusted contributor 确认
     → canary 灰度 5% → 观察 7 天无异常 → stable 全量
     → 版本化 + 签名下发 → 客户端可回退到内置 baseline
```

- 2 人 review 必须是两位不同 trusted contributor；作者不能 review 自己的观测派生规则。
- canary 期间监控：该规则的误报反馈数、用户「提交观测」反对数。异常立即回滚。

## 4. 置信度模型

`confidence = f(独立观测数, 设备多样性, 时间新鲜度)`

| 因子 | 说明 |
| --- | --- |
| 独立观测数 | 去重后（按 deviceIdHash + 通道）的观测条数，越多越高 |
| 设备多样性 | 不同 OEM / ROM 族 / 型号数，多样性越高越可信 |
| 时间新鲜度 | 越近的观测权重越高；**按季度衰减** |

- 衰减：每季度对 `confidence` 乘以衰减因子；低于阈值（建议 0.6）自动降级为 `pending_review`。
- 失效率目标：< 10% / 季度（v1.1 §3.3 社区指标）。

## 5. 冲突处理

- 同条件多候选 → **全部保留，按 confidence 排序展示**，UI 显示「多个候选」。
- 不强行覆盖、不人工选唯一真相。
- 冲突率目标：< 5%（v1.1 §3.3 社区指标）。

## 6. 版本化与回滚

- 规则带 `version` / `since` / `supersedes` / `verifiedAt`。
- 客户端内置签名 baseline 快照；在线规则包异常可一键回退。
- 规则包签名校验失败 → 拒绝加载，退回 baseline。
- 每次 stable 发布生成 changelog（新增/修改/废弃规则 + 证据观测）。

## 7. 激励

- 贡献者榜单、规则 `evidence[]` 署名、设备覆盖度看板。
- B 端客户可见的设备覆盖度作为采购参考——让贡献产生可见价值。

## 8. 冷启动

- 内置 Top 30 机型/ROM 族 × 5 类 baseline 快照（见 `rules/baseline/`）。
- 未识别目录一键「提交观测」，把用户转化为贡献者。
- 目标：baseline 对真机矩阵的目录→标签覆盖率 ≥ 60%（v1.1 §3.3）。

## 9. 角色与权限

| 角色 | 权限 |
| --- | --- |
| 普通用户 | 提交观测；查看规则 |
| trusted contributor | 审核观测派生规则（2 人制） |
| maintainer | 合并 stable、发布签名规则包、管理 trusted 名单、执行回滚 |

## 10. 指标看板（对应 v1.1 §3.3）

| 指标 | 门槛 |
| --- | --- |
| baseline 目录→标签覆盖率 | ≥ 60% |
| 未识别目录「提交观测」转化率 | ≥ 10% |
| 审核吞吐 / 冲突率 | ≥ 20 条/周，冲突率 < 5% |
| 置信度衰减后规则失效率 | < 10% / 季度 |
